# Read-only agent architecture

Stage 4 adds an optional `app/agent` subsystem to the existing FastAPI monolith.
Its local Ollama and optional OpenAI adapters, orchestration, tool registry/execution, evidence verification,
conversation storage and contracts are separate from routes. It delegates all
business calculations to Stage 2 and all retrieval/source verification to Stage 3.
There are no new business tables, migrations, retrieval indexes or write APIs.

The provider receives a user message, fixed trusted instructions and explicit tool
schemas. Ollama dynamically requests functions through native `/api/chat`; explicitly
selected OpenAI uses the Responses API. The server
parses and validates each call, establishes the same business cutoff, validates
entity existence, runs the approved function under a restricted database role,
validates its response and returns a `function_call_output` containing an evidence
ID. All response output items, including encrypted reasoning, are replayed inside
the same bounded request. Source text never becomes a system/developer message.
Final structured findings undergo server verification before an answer is rendered.

There is no production fake-provider mode, question-to-workflow dispatch, canned
business answer or provider-controlled Python/SQL execution. Test doubles live in
tests and are explicitly labelled `offline_test`. Control/error messages are
deterministic; business interpretations are generated by the configured model.
**Live LLM execution is not accepted until a real configured provider succeeds.**

`POST /api/v1/agent/query` accepts question, optional conversation ID, as-of,
business context and lower request limits. `GET /status` exposes configuration
state without network calls or secrets; `GET /tools` describes approved contracts.
Missing local models or unavailable Ollama return explicit provider errors; missing
optional OpenAI credentials return `provider_not_configured` with no invented answer,
token usage or evidence. Existing analytics and retrieval continue to work.

The historical cutoff defaults to 2026-09-30; supported agent cutoffs are inside
the observed Stage 2 period. Every tool call uses that cutoff. Explicit conflicting
tool dates fail rather than silently switching periods. Each numeric projection
retains its original observation window. Knowledge citations must reference the
effective version at the same cutoff, including before a tool result reaches the
model. General policy and supplier-specific scope remain separate.

Conversations are a single-process, local-demo memory store: opaque IDs, maximum
50 entries, idle expiry after 30 minutes, maximum four retained turns and per-session
locking. History retains bounded verified findings and actual entity references,
not entire provider transcripts/tool payloads or reasoning. Follow-ups inherit the
cutoff; changing it requires a new conversation. Prior evidence IDs cannot support
a current finding without fresh tool evidence. Sessions disappear on restart.
These are ownership conventions, not authentication or tenant isolation.

At most two queries execute concurrently. Queue waiting consumes the request's
global deadline. Tools run sequentially in bounded workers with PostgreSQL statement
timeouts and cancellation attempts; late/cancelled results cannot be published.
Limits and timing/usage metadata are described in [LLM_INTEGRATION.md](LLM_INTEGRATION.md).
Model errors, incomplete output, invalid arguments, missing evidence and exhausted
budgets produce explicit error/partial states. Validated partial evidence is retained.

See [tool contracts](TOOL_REGISTRY.md), [grounding](AGENT_GROUNDING.md),
[security](AGENT_SECURITY.md) and [evaluation](AGENT_EVALUATION.md).

## Stage 4B reliability additions

Clear prohibited execution requests are refused before constructing a provider.
The ultimate action boundary remains registered read-only tools and the database
role; informational procedure questions stay eligible for evidence retrieval.
Optional candidate selection/finalization flags both default false. The local model
chooses capabilities, then tool calls, then short evidence references with typed
interpretations. Every phase consumes the original budgets. A final evidence ledger
replaces duplicate transcript replay, retaining selected metric definitions, full
source passages and scope. See [context optimisation](CONTEXT_OPTIMISATION.md).

Conversation memory now retains completed verified subject/metric selections and
ranking order, without model narrative. Failed responses cannot seed a supposed
ranking. Fresh current-run evidence is mandatory. Expiry, locks, cutoff and local
ownership limits remain unchanged. [Stage 4B acceptance](STAGE4B_REPORT.md) is open.
