# Intent, entity resolution and planning

The grammar composes ontology nouns, numerical/named mentions, comparison/ranking
operators, defined metrics, source facets and ISO/month date scopes. Structured
`objectives`, `entities`, `start_date` and `end_date` are also accepted and validated.
Unknown metrics/capabilities and incompatible dates cannot become executable tools.
Ambiguous language produces clarification, or a bounded local semantic-frame attempt
in hybrid mode. Model-returned numeric identifiers must already occur as typed
mentions; returned name spans must occur in the question and still pass database
resolution. The model cannot change cutoffs or turn retrieved text into instructions.

Entity IDs/names come from the existing resolver and visible database records.
Employee/customer/invoice/shortage lookup was added to that same allowlisted tool;
the tool count stays seventeen. Name discovery uses fixed tables, bounded reads,
parameterized cutoffs and the read-only role. Ambiguous/nonexistent names are not
replaced with guessed entities.

The registry binds capabilities to actual tools and required evidence classes.
Supplier SLA plans require supplier metrics plus that supplier's contract reference
and metadata-filtered agreement retrieval. Policy title matching narrows eligible
Stage 3 documents dynamically; there are no production source-code IDs or expected
business values. Multiple overlapping contract assessments remain separate and
prevent a falsely complete single-agreement answer.

Rankings use complete Stage 2 populations, stable identity ties and nulls last.
The existing ranking wrapper also supports recorded open commitment, using its
existing complete supplier snapshot. A rank-extreme contract request binds the
next detail step to the actual ranked row, then the agreement step to its actual
contract. This is not a fixed supplier workflow.

Each plan exposes ordered steps, dependencies, argument scope, evidence requirements,
completion conditions, cost estimate and limits. Duplicate calls use canonical typed
arguments. Investigation pages expand only within budget; uncovered populations
produce a partial answer. If a bounded investigation exposes actual linked shortage,
sales-order or incident IDs, at most two dependent roots are explored. Complete
root investigations avoid redundant expansion. Links are associations unless the
existing dataset explicitly labels a simulated chain.

Comparisons can expand one supported entity dimension, such as two suppliers' costs
or two warehouses' inventory. Unsupported customer aggregate filters, ambiguous
multi-dimension combinations and excessive investigation roots require clarification.
The grammar is intentionally conservative; it does not understand every English
paraphrase. Missing language inference is visible in execution metadata.

Conversation state is bounded, in-process and lost on restart. First-two references
require a completed verified ranking, preserving real rank order and cutoff. Failed
or partial investigations are not facts for later turns. Explicit references are
resolved again. Elliptic historical follow-ups may reuse the typed objective of one
completed non-ranking subject, obtaining fresh evidence for the requested period;
ambiguous prior rankings cannot silently become a different historical ranking.
