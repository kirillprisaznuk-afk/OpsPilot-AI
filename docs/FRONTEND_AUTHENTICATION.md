# Frontend authentication and security boundary

The frontend uses the existing Stage 5 identities and bearer API. Sign-in sends the real username/password only to the local server. The backend returns an opaque bearer to Next.js. The browser receives a random 256-bit reference in an httpOnly, SameSite=Strict cookie. The server persists the bearer and CSRF secret in an AES-256-GCM encrypted file, keyed by a hash of that reference. The small project-scoped session volume survives a service restart. The encryption key is server-only and private to the volume; possession of the host/volume is outside the local demo trust boundary.

Cookies are Secure when the configured origin uses HTTPS. The documented local origin is plain HTTP on `127.0.0.1:3106`; no production TLS or internet deployment is claimed. Cookie mutations require the exact configured origin, JSON, and a constant-time comparison of the session-bound CSRF header. Login also checks origin. The browser stores no bearer/password in localStorage or sessionStorage. SessionStorage only retains hashed operation identifiers and UUID idempotency keys for recovery.

Protected gateway calls validate the same per-user backend bearer with `/auth/me`, require current membership, and forward only enumerated supported paths/methods. No shared admin identity, client actor override, model provider route or arbitrary path proxy exists. Conversation IDs are signed to the current browser session before exposure and verified before reuse; a different session cannot resume another user's frontend conversation. Backend logout revokes the real session; frontend removes its record and clears caches. A backend 401 clears visible session data and returns to sign-in. A 403 stays a permission error.

Stage 7 also verifies ownership inside FastAPI for authenticated hybrid queries. The live session UUID owns the in-memory context. Anonymous direct callers keep their own contexts and cannot resume a browser-owned conversation even with its raw ID. If the API restarts, start a new conversation when the prior in-memory context expires.

The frontend hides unsupported role actions and requires deliberate confirmation of the exact proposal digest. This supplements, rather than replaces, server authorization, immutable payload/approval checks, transaction rollback, idempotency and audit. The old direct read-only FastAPI routes retain their original local exposure on loopback; Stage 6 adds no public host binding. Local-demo limits include no SSO/MFA, no public signup, no distributed session store, no background cleanup job and no production deployment assertion. The local CSP allows inline framework scripts; untrusted business text is never interpreted as HTML. Production would require a separate nonce/TLS/IAM and retention review.
