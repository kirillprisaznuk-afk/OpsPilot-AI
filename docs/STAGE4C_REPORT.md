## Demonstrated failures and corrections

- Initial grammar treated possessive observation-volume language as prior-answer
  reference and plural purchase/customer orders as individual roots. General rules
  were corrected; affected original/unseen cases and full suites reran.
- Over-eager conditional expansion made a complete customer-order investigation
  partial. Expansion now requires incomplete root coverage and prioritises actual
  linked shortage/customer roots; it never guesses IDs.
- Initial relationship presentation hid the important late-replenishment chain.
  Relevance ordering, exact quantities and a dedicated why-answer test corrected it.
- Verification initially selected only some links in each draft. All selected
  relationships now pass bounded independent verification. Unverified graph facts
  cannot be rendered. Source text/metadata are checked independently, including
  tests where both the graph and a forged tool payload agree with each other.
- An early added oracle matcher let a nested null filter erase an outer detail ID,
  falsely failing the two-supplier comparison. Scope matching was corrected without
  altering expected business facts. The final evaluator passes every scoped oracle.
- An initial evaluator request raced container readiness and disconnected before
  application startup. The evaluator now waits for /ready before measured requests.
- The global Windows pytest temporary directory denied access. Tests reran using a
  fresh project-local temporary directory; no failure was skipped or relaxed.
- Resource admission repeatedly blocked before inference. This remains unresolved
  and is reported as BLOCKED, never a successful model run.
