# Stage 7 security audit

The release boundary is one loopback Windows workspace with synthetic data. An unauthenticated browser, a scoped user, a stolen or stale session reference, another department, untrusted document content, and a replayed or interrupted request are distinct threats. A host administrator, the database owner, and code running with application service credentials are trusted within this boundary. Direct historical read endpoints remain loopback surfaces. The browser gateway requires identity and current membership.

| Area | Verification |
|---|---|
| Authentication | Real Edge sign-in and sign-out as operator, reviewer, analyst, viewer and admin. Isolated PostgreSQL exercises unknown and incorrect credentials, disabled principals, expiry, revocation and persistent throttle. Argon2id and opaque, hashed backend bearer sessions remain in use. |
| Browser sessions | The cookie is httpOnly, SameSite Strict, host-only and scoped to `/`. Loopback HTTP is the tested deployment. The Secure flag under HTTPS is configured from the origin and was reviewed in source. The backend bearer stays behind Next and is encrypted in the project volume. |
| Gateway | Explicit method and route allowlist, current backend membership, JSON media type, bounded bodies, exact origin and session-bound CSRF. Browser tests refuse missing or revoked identity, forged origin, missing CSRF, provider mode, arbitrary agent path and forged context. |
| Authorization | Actual operator and reviewer have department 1 scope. The workflow backend rechecks authorizations and ownership. Disposable tests exercise self-approval, outsider access, viewer writes, cross-scope pagination and revoked authority. Global admin still cannot approve its own proposal. |
| Context isolation | Stage 6 revealed the backend conversation ID as part of the signed handle. The Stage 7 probe continued a signed-in ranking anonymously with the ID prefix. FastAPI now binds its in-memory context to the verified backend session. Anonymous direct requests can use their own contexts, with no access to browser-owned ones. The Edge regression checks denied reuse in another browser session and direct 404, then repeats the real follow-up with the owning session. |
| Approval and replay | The exact digest and version, distinct reviewer, scope, fresh policy, evidence and target are rechecked. Concurrent approval records one decision. Same-key and different-key execution races record a single effect. |
| Audit and failure | Runtime roles cannot modify historical tables or rewrite the append-only audit. Receipt and audit insertion failures, deferred commit failure and execution interruption are tested only in disposable PostgreSQL. The browser confirms a lost execution response by reading the authoritative receipt before retry. |
| Untrusted content | Stored attack strings render as plain text in workflow details. Registered source links are constructed with typed IDs. Retrieved text and model output cannot authorize a write. Browser tests verify inert markup and zero inference in deterministic mode. |

The request guard previously accepted media types beginning with `application/json`. An actual request with `application/json-other` reached downstream validation. The guard now checks the exact type and allows parameters such as charset. The same request returns 415.

The npm registry production audit reported zero findings. The full audit reported one moderate development-only dependency issue in `minimatch` 10.2.6 through TypeScript ESLint. The current parent still requires minimatch 10 and the advisory's fix requires 11. The affected dependency is used during local linting, outside the application server request path. Python audit found zero known issues in the 49 locked runtime distributions scanned for this Windows environment. Advisory results are point-in-time observations. [Minimatch advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249) · [Next.js security releases](https://github.com/vercel/next.js/releases/tag/v16.4.5) · [React RSC advisory](https://github.com/react/react/security/advisories/GHSA-xqc2-xf4c-x3h3)

The local server uses a CSP with inline framework scripts. Production TLS, independent tenant isolation, MFA, external audit anchoring and retention are outside the tested deployment. The existing authentication origin throttle intentionally shares a local gateway budget. Runtime health and rate limits were evaluated at bounded local load.
